01

The idea: remember subproblems

You have a bag with limited capacity. Each item can be taken once or not at all.

The goal is to maximize total value without exceeding the bag's capacity. A greedy choice—always taking the most valuable item—can fail, because a smaller combination may be worth more.

Dynamic programming recipe
1. Define a smaller state.
2. Find how states depend on one another.
3. Store each answer and reuse it.

02

Turn the story into a recurrence

Define the state

Let dp[i][w] mean:

the maximum value using the first i items
when the capacity is w

For each item, we have exactly two choices:

skip item
dp[i−1][w]
or
take item
value + dp[i−1][w−weight]

dp[i][w] = max(
dp[i−1][w],
valueᵢ + dp[i−1][w−weightᵢ]
)

Why does this work?

If we take an item, the remaining capacity and earlier items form a smaller knapsack problem. That is optimal substructure.

Different choices often ask for the same smaller problem. Storing its result avoids recalculating it. That is overlapping subproblems.

Exam language: 0/1 means each item is either 0 (not chosen) or 1 (chosen). You cannot take half an item or take it twice.
